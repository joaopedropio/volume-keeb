# volume-keeb

Volume-control knob on a Waveshare RP2040-Zero with an HW-040 rotary encoder (a KY-040 is meant to work too: same pins), running QMK. README.md is the build guide for people making their own (parts, printing, wiring, flashing, assembly, host setup); `docs/DEVELOPMENT.md` holds the technical notes (driver, protocol, case internals). Keep both in step when behavior, pins or parts change.

Sibling project to [single-keeyb](https://github.com/joaopedropio/single-keeyb) (a separate Space-key macropad on the same MCU). The encoder was originally prototyped on the single-keeyb board, then pulled out into this standalone project — don't merge the two back together.

## Repo layout

- `qmk/waveshare_rp2040_zero_volume/` — the actual QMK custom keyboard definition (`keyboard.json`, `config.h`, `halconf.h`, `mcuconf.h`, `rules.mk`, `keymaps/volume/keymap.c`, `graphics/*.qff.c`). This is the single source of truth.
- `host/` — the host app, Linux and Windows. `volume_sync.py` is only the entry point (the systemd unit, `flash.sh` and the Windows build start it); the code is the `volume_keeb/` package: `engine.py` (reader + sync threads), `knob.py` (hidraw on Linux, hidapi elsewhere), `audio_linux.py` (`pactl` + MPRIS) / `audio_windows.py` (pycaw + pywinrt media sessions), `web.py` + `web/index.html` (settings page on `localhost:8137`: preset, six colors, decor, menu layout, screensaver + screen-off timer, fonts), `qff.py` (TTF→QFF without the QMK CLI), `config.py`, `tray.py` (pystray, optional on Linux), `autostart.py` (Windows Run key), `updates.py` (checks GitHub's latest release; installs its `.uf2` on the knob from the page), `version.py` (reads the repo's `VERSION`). `requirements.txt` and `build_windows.ps1` (PyInstaller `.exe`) are next to it, with the udev rule and the systemd user unit. The Windows backend was written without a Windows machine to test on. Raw HID packet formats: host→device `0x60`/`0x61`/`0x62` (begin/entry/end of an app-list snapshot), `0x54` (title chunk for the app with media), `0x63` (preset theme, an index into `keymap.c`'s `themes[]`), `0x64` (reboot into the BOOTSEL bootloader, sent by `volume_sync.py --bootloader` from `flash.sh`), `0x65` (palette: six HSV colors + decor), `0x66`/`0x67`/`0x68` (font upload begin/data/end), `0x69` (clear a font slot), `0x6A` (query font slots), `0x6B` (screensaver kind, its idle time, screen-off time, start-now flag, menu layout), `0x6C` (query the firmware version), `0x6D` (query the knob's settings); device→host `0x70` (set volume / toggle mute / play-pause for one app id), `0x71` (font command status), `0x72` (font slot CRCs), `0x73` (firmware version), `0x74` (the knob's settings, and whether they were changed on the knob). Both the layout and the numeric command values are defined in `volume_keeb/protocol.py` and `keymap.c` — keep them in sync.
- `case/` — the 3D-printed case. `volume_case.scad` is OpenSCAD and parametric, written in the style of dongle-slayer's `case/dongle_case.scad` (branch `case-3d`), which is also where the NV3007 module's numbers come from. `gen_case.sh` exports `volume_case-{top,base}.stl` and the stand-ins' pieces in `view/` for `viewer.html`, a plain WebGL view adapted from dongle-slayer's `web/js/case3d.js` (all kept in git). `deploy_pages.sh` copies the page and the STLs to the GitHub Pages site repo (`~/joaopedropio.github.io`, live at https://joaopedropio.github.io/volume-keeb/). This repo holds the canonical page and the site gets a copy, so after changing the model or the page, rerun both scripts and push both repos and fails unless `part="check"` and `part="insert"` both come out empty.
  - Every part is mounted on the base, and the top only covers it. The knob goes through a plain hole with no floor, so the top lifts off over it.
  - Every screw goes into an M2 heat-set insert.
  - The RP2040-Zero lies upside down so that BOOT/RESET can be pressed through holes in the bottom.
  - The encoder is chosen with `encoder`. Only `"hw040"` is measured: its numbers come from `hw-040-encoder-module.stp` and `hw-040-module-dimensions.webp` in the repo root. The RP2040-Zero's come from `rp2040-zero-2.snapshot.6/` (the "without headers" STEP).
  - `"ky040"` deliberately fails an `assert` until real measurements are added to `enc_dims()`. Don't fill it with guessed values.
  - The root's `maxmix_base_*.stl` are only a visual reference for the shape. The reference STL/STEP files stay untracked.
- `docs/wiring.svg` — the README's wiring picture, written by `docs/gen_wiring.py` (stdlib only, adapted from dongle-slayer's `tools/gen_wiring.py`; kept in git). Each part is drawn from the side it's soldered on and to scale from `volume_case.scad`'s numbers. Rerun it when pins change, along with the README's tables.
- `tools/ui_sim/` — renders the volume keymap's screens to PNGs on the PC: `run.py <outdir>` compiles the real `keymap.c` and Quantum Painter (from `~/qmk_firmware`) against an RGB565 surface, with `stub/` standing in for the rest of QMK, and writes the menu and app screens for every theme. Use it to check UI changes before flashing; `UI_SIM_FONTS=<dir>` loads `slotN.qff` files as uploaded fonts (`tools/ui_sim/font_store_sim.c`).
- `install.sh` — the Linux host setup for end users: distro packages (apt/pacman/dnf, pip fallback for pystray), the udev rule, the systemd user unit pointed at the clone, an app-menu entry. `--uninstall` undoes it. Windows uses `host/build_windows.ps1` instead.
- `flash.sh` — builds the firmware, reboots the running knob into BOOTSEL over Raw HID (`volume_sync.py --bootloader`), waits for `RPI-RP2` and copies the UF2. `--no-build` skips the build; a `.uf2` path as the argument flashes that file instead (how end users update from a release).
- `VERSION` — the one version number: the firmware build (keymap `rules.mk` → `FW_VERSION_*`), the host app (`version.py`) and the release workflow (tag must equal `v$(cat VERSION)`) all read it. Bump it in the commit a release is tagged on.
- `.github/workflows/release.yml` — on a `v*` tag, builds `volume-keeb.uf2` (QMK's `qmk_cli` container, `qmk_firmware` pinned by `QMK_REF`) and `volume-keeb.exe` (`build_windows.ps1` on a Windows runner) and publishes them with the case STLs as a GitHub release. The README tells end users to download these instead of building, and links to `releases/latest/download/<file>`, so keep the asset names stable.
- `keymaps/volume/font_store.c` — fonts uploaded from the settings page, kept in 3 × 64 kB flash slots from 1 MB (`FONT_STORE_*` in `config.h`), which survive reflashing. An uploaded font must have the same line height as the built-in one it replaces (13/27/24 px); `qff.py` sizes it to fit.
- `qmk/waveshare_rp2040_zero_volume/graphics/*.qff.c` — Quantum Painter fonts, regenerated (not hand-edited) with `qmk painter-make-font-image` + `qmk painter-convert-font-image` from DejaVu Sans Mono; see the header comment each file carries for the exact invocation.

## Firmware architecture

QMK builds require the keyboard directory to live inside a `qmk_firmware` checkout at `keyboards/handwired/onekey/waveshare_rp2040_zero_volume/`. Rather than keeping two copies in sync, that path is a **symlink** into this repo's `qmk/waveshare_rp2040_zero_volume/`. If a fresh `qmk_firmware` checkout is ever made, recreate the symlink — don't copy the files:

```sh
ln -s /path/to/this/repo/qmk/waveshare_rp2040_zero_volume ~/qmk_firmware/keyboards/handwired/onekey/waveshare_rp2040_zero_volume
```

Edit keyboard/keymap files only inside this repo, never through the symlink target's other path — they're the same files, but editing via the repo path keeps `git status` sane.

### No separate matrix key — the encoder's SW pin is the only key

QMK requires every board to have at least one matrix key defined in a `LAYOUT` (a `layout: []` with zero entries fails linting: "No LAYOUTs defined!"). An encoder's rotation pins (`pin_a`/`pin_b`) are handled entirely separately from the matrix by `quantum/encoder.c` — they never count as a matrix key. So this board's single matrix entry is the HW-040's own `SW` pushbutton pin (GP29), mapped to a custom `ENC_CLICK` keycode whose meaning (menu select / back-to-menu / double-click pause / hold-to-mute; without a host app: open the knob's settings / edit a setting, hold for the mute media key or to leave the settings) depends on which screen is active; `GP27`/`GP28` (CLK/DT) are declared only under `encoder.rotary` in `keyboard.json` and don't appear in the matrix at all. This is why the board can live under `handwired/onekey/` (which enforces a 1x1 `LAYOUT_ortho_1x1`) despite having no separate physical button — the encoder's built-in switch satisfies that requirement.

## Why QMK, not KMK/CircuitPython

CircuitPython's `usb_hid` module (and therefore KMK, which sits on top of it) has no implementation of the USB remote-wakeup protocol — confirmed via an open upstream issue, [adafruit/circuitpython#8774](https://github.com/adafruit/circuitpython/issues/8774). That makes wake-from-suspend impossible on that stack. Don't reintroduce CircuitPython/KMK for this project.

## Build toolchain notes

- The current dev machine is Ubuntu 24.04: QMK CLI via `pipx install qmk` (→ `~/.local/bin/qmk`), `qmk_firmware` shallow-cloned at `~/qmk_firmware`, ARM toolchain via `apt` (`gcc-arm-none-eabi`, `libnewlib-arm-none-eabi`, `binutils-arm-none-eabi`). The Arch notes below are from an earlier machine.
- QMK CLI was installed via `pip install --user qmk` under a pyenv-managed Python (system Python is externally-managed per PEP 668 on this Arch machine) — landed at `~/.local/bin/qmk`.
- ARM toolchain (`arm-none-eabi-gcc`/`newlib`/`binutils`) and `dfu-util` come from the Arch `extra` repo via `pacman`.
- Flashing is drag-and-drop UF2 (BOOTSEL bootloader), not `qmk flash`/`dfu-util` — mount the `RPI-RP2` drive and copy the `.uf2` in. `flash.sh` does all of that, buttons included, as long as the running firmware knows the `0x64` bootloader command.
